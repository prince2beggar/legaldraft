# AIN-AI — Architecture & Product Decisions Log

**Last Updated:** 2 October 2026  
**Document Owner:** Lead Engineer & Product Owner  

This document records architectural, technical, and product design choices made during development, along with context, rationale, and open questions.

## 1. Approved Decisions

| ID | Topic | Decision | Rationale | Status |
| :--- | :--- | :--- | :--- | :--- |
| **ADR-001** | Monorepo Structure | Monorepo containing `apps/`, `services/`, `packages/`, `content/`, `evals/`, `infra/`, and `docs/`. | Keeps Trust Kernel, schemas, i18n, and modules unified while supporting independent container deployments. | Approved (SRS §2.3) |
| **ADR-002** | Default Language | Bangla (`bn`) as primary/default locale; English (`en`) secondary. | Targeted at Bangladesh citizens; minimizes foreign terminology and ensures native accessibility. | Approved (SRS §0.3, B9) |
| **ADR-003** | Trust Kernel Centrality | Modules never query AI models or external sources directly; all requests route through Trust Kernel and AI Gateway. | Guarantees citation verification, source grounding, and auditability on 100% of legal claims. | Approved (SRS §2.1) |
| **ADR-004** | Deterministic Deadlines | Deadlines, limitation periods, and statutory countdowns are computed exclusively by pure-code rules engine, never LLMs. | Eliminates date hallucination, preventing critical missed court filings and legal liability. | Approved (SRS §0.3, B6, HR-08) |
| **ADR-005** | Legal Content Integrity | Zero legal statutes, sections, court precedents, or emergency numbers may be generated from AI memory; all seeded content starts as `DRAFT_NOT_REVIEWED`. | Prevents legal misinformation and adheres to unauthorized practice of law (UPL) boundaries. | Approved (SRS §0.3, B3) |
| **ADR-006** | Mock SMS Provider in S0/S1 | Use an in-memory/mock SMS provider interface for S0/S1 until an official Bangladesh aggregator is contracted. | Allows local development, deterministic test automation, and CI test suites to pass without third-party vendor lock-in. | Approved (Sprint S0 Rule) |
| **ADR-007** | Dual-Database Compatibility | Use SQLAlchemy 2.0 ORM with PostgreSQL + pgvector as primary production target, with SQLite fallback support for lightweight local offline development. | Enables zero-setup local dev while matching production cloud database architecture. | Approved |
| **ADR-008** | PII Redaction in Logging | Structured JSON logging with automated redaction filters for phone numbers, email addresses, NID numbers, passwords, and tokens. | Complies with draft PDPO requirements and data security standards. | Approved (SRS §8.3, B15) |
| **ADR-009** | Unified Application Port 8088 | Standardize application web shell, admin, and core API on single port `8088` across local and Docker environments. | Eliminates port collisions with other local developer tools and guarantees consistent links across Docker and host. | Approved |
| **ADR-010** | Single-Command Local CI Pipeline | `python run_ci.py` executes Ruff linting, Mypy type-checking, Pytest 29-test suite, reversible migrations, and Axe a11y shell audit. | Ensures identical checks run in GitHub Actions CI and developer workstations without setup friction. | Approved |
| **ADR-011** | Legacy Route Protection | Protect legacy Advocate dashboard (`/`) and legacy API routes with `get_current_user`. Restrict `/admin` to `admin` and `reviewer` roles (403 for citizens). | Prevents unauthorized data leakage of sensitive legal cases, client information, and draft deeds. | Approved (SRS §9.3 S1, X-001) |
| **ADR-012** | Standard Vetted PyJWT Integration | Replaced initial hand-written JWT encoder with vetted `PyJWT` library (v2.15.1). Algorithm pinned strictly to `HS256`, constant-time signature comparison, enforced `exp` and `nbf` validation, secret sourced strictly from environment (`JWT_SECRET`), and rejection of tampered, expired, and `alg=none` tokens verified in `test_jwt_security.py`. | Eliminates cryptographic edge-case vulnerabilities; conforms to industry-standard token security best practices. | Approved (S1 Fixes) |
| **ADR-013** | Neutral SMS Gateway Adapter Slot | `MockSmsProvider` remains default for local development, deterministic tests, and CI. Production SMS slot named generically as `RealSmsAdapterSlot` (`REAL_SMS_ADAPTER_CLASS`); no vendor is treated as pre-selected pending Question Q3. | Prevents premature vendor lock-in while preserving plug-and-play production gateway integration. | Approved (S1 Fixes) |
| **ADR-014** | Salted Hash Blocklist for Deleted Accounts | Plain phone numbers are never stored in the blocklist. `AuthService` computes a salted SHA-256 hash using a server-side salt (`PHONE_BLOCKLIST_SALT`), storing only the irreversibly hashed identifier in the database. | Complies with data minimization and prevents storing plain personal identifiers of deleted users. | Approved (S1 Fixes) |
| **ADR-015** | Provisional Permanent Block Status (Q8) | Permanent phone blocking post-account deletion is marked as provisional, pending legal counsel's decision on Question Q8 (balancing citizen right-to-be-forgotten under Draft PDPO vs abuse/fraud prevention). Confirmed that deletion strips or anonymizes PII per SRS 8.4 while preserving append-only audit continuity. | Ensures regulatory alignment before commercial deployment in Bangladesh. | Provisional (Pending Q8) |
| **ADR-016** | Real Database Persistence for Trust Kernel | Users, devices, versioned consents, blocked phone hashes, and audit ledger are stored in the real database layer (`trust_users`, `trust_devices`, `trust_consents`, `trust_audit_logs`, `trust_blocked_phone_hashes`) via SQLAlchemy ORM. All services rehydrate from DB on startup, maintaining cryptographic hash chain continuity across restarts. | Satisfies Section 9.3 S1 persistence requirements and eliminates memory-only volatility. | Approved (S1 Fixes) |
| **ADR-017** | Legacy Route Cross-Tenant Isolation & PolicyConsent.can | All legacy `/api/v1/*` routes enforce tenant isolation and authorization via `PolicyConsent.can(actor, action, obj)`. Matters and documents are scoped to owner; cross-user reading, editing, drafting, and health auditing return HTTP 403 Forbidden. All `/api/v1/admin/*` endpoints strictly restricted to `admin` and `reviewer` roles. Verified with negative sweep tests (`test_ownership_isolation.py`). | Fulfills requirement X-001 (role AND ownership/consent, not login alone). | Approved (S1 Fixes) |
| **ADR-018** | Responsive by Default Architecture | Every screen and UI component across the entire project is responsive by default. Mobile-first design starting at 360px; breakpoints: mobile < 640px (bottom 5-tab bar, single column, bottom sheets), tablet 640-1023px (slim side rail, 1-2 columns), desktop >= 1024px (full left sidebar, 2-3 columns, modal dialogs). Fluid CSS grid/flex and clamp() typography. Tap targets >= 44x44px. No horizontal overflow at any viewport. Shared layout shells (`AppShell`, `PageContainer`, `ResponsiveGrid`, `ResponsiveTable`) in `packages/ui_kit`. Viewport automated testing at 360x640, 768x1024, and 1280x800 via Playwright. Included as Item 11 in Definition of Done (SRS §9.4). | Eliminates duplicate mobile/desktop codebases, ensures native accessibility for 85%+ smartphone users in Bangladesh, and prevents UI regressions. | Approved (Permanent Project Rule) |
| **ADR-019** | Ingestion Pipeline & Hybrid Retrieval Architecture | Source ingestion executes as an asynchronous multi-step pipeline (`uploaded` -> `extracted` -> `cleaned` -> `classified` -> `chunked` -> `indexed` -> `review_pending`) with per-step tracking in `ingestion_jobs` and retry capability (AC-M10-6). Review enforces strict uploader-approver separation (`approver_id != uploader_id`, AC-M10-1). Legal versioning automatically bounds predecessor `effective_to` and blocks on date overlap (AC-M10-2), paired with passage diff computation. Hybrid retrieval merges lexical keyword overlap with 128-dim normalized dense vector cosine similarity (`DeterministicEmbedder`), strictly enforcing closed corpus constraints: unapproved versions are completely invisible to citizens (AC-M09-2, AC-M10-3) and results are filtered by `effective_from <= as_of_date <= effective_to` (AC-M09-1). Rights badges display access tier, and unlicensed content omits text with link only (AC-M09-3). Explanations display AI label, source chip, and as-of date (AC-M09-4). PostgreSQL pgvector adapter (`PgvectorEmbedder`) is explicitly marked UNVERIFIED until run in Postgres 16 in CI/Docker. | Guarantees auditability, temporal correctness, copyright compliance, and hallucination-free legal retrieval. | Approved (Sprint S2) |

| **ADR-020** | Ingestion Step Status & Pre-S3 Static Explanations | Pipeline steps are tracked with explicit implementation status: `uploaded` (Real), `extracted` (Stubbed: UTF-8 decode, no Tesseract OCR installed), `cleaned` (Real: text normalization), `classified` (Stubbed: regex keyword heuristics), `chunked` (Real: section/paragraph chunking), `indexed` (Real: DeterministicEmbedder; Pgvector UNVERIFIED pending Postgres), `review_pending` (Real: DB state & dual-custody queue). Execution is in-process async. In Library explanations (M09), zero AI model generation is permitted before S3 (AI Gateway & Citation Verifier); endpoints and UI display clearly labelled static placeholders `STATIC_PLACEHOLDER_NO_AI` (`[DRAFT_NOT_REVIEWED / STATIC PLACEHOLDER]`). | Enforces strict compliance with core rules B1-B15 and HR-07 preventing unverified AI content before safety gate modules exist. | Approved (Sprint S2) |
| **ADR-021** | Rules Engine, Citation Verifier, AI Gateway, and Eval Harness Architecture | (1) **Rules Engine**: Belongs to the **Trust Kernel** (not M11/Intake); executes pure deterministic code for statutory periods (`relative_period.calendar_days.v1`), configurable trigger-day inclusion, empty holiday calendar with `EMPTY_FAKE_TEST_DATA` label, and strict **Decision D6 (ADR-004)** provenance enforcement (`UnverifiedDeadlineError` blocks ungrounded AI deadline dates). (2) **Citation Verifier**: Exact verbatim span validation, normalized text tolerance (Unicode NFKC, whitespace, quotes, Bengali/English digits), and temporal validity against `effective_from`/`effective_to` with rejection of non-existent/unapproved/superseded versions and numeric alterations. (3) **AI Gateway**: Versioned prompt registry (unregistered refused), prompt injection defense & flagging, pre-provider reversible PII redaction (BD mobile, NID, email), model routing with fallback, JSON-schema validation, token cost guard, `FakeLLMProvider` and neutral disabled `RealLlmAdapterSlot`, recording every generation and claim in `ai_outputs` and `claim_links`. (4) **Eval Harness**: Golden test suites labeled `FAKE_TEST_DATA`, latency metrics, legal quality gates requiring **zero critical errors** and suite-defined minimum scores, persistence in `eval_runs` and `eval_results`. (5) **Responsive Admin**: `/admin/rules` and `/admin/evals` compliant with ADR-018 across 360, 768, and 1280px. | Enforces strict legal safety (Decision D6, Rules B3, B6, B15), data minimization/PDPO privacy, and auditable hallucination defense. | Approved (Sprint S3) |
| **ADR-022** | Document Object Storage & Resumable Upload Architecture | Abstract `ObjectStore` interface with `LocalFilesystemObjectStore` as default verified storage engine and `MinioObjectStoreAdapterSlot` marked UNVERIFIED (falls back cleanly until MinIO daemon is provisioned). Multi-tenant folder scoping (`{owner_id}/{doc_id}/...`), SHA-256 hash deduplication to eliminate duplicate file storage, chunked resumable upload API with automatic reassembly and offline IndexedDB/ServiceWorker queue, and irreversible purge with zero-sensitive-content audit ledger recording (`trust_audit_logs`). | Complies with SRS §5.3, §8.4, AC-M03-5, and AC-M03-6; enables high-performance local development while ensuring seamless cloud object store drop-in. | Approved (Sprint S4) |
| **ADR-023** | Document Ingestion OCR Pipeline & Host-Independent Adapter Slot | Abstract `OcrEngine` interface with `FakeOcrEngine` as deterministic benchmark runner for synthetic scans (`clean`, `rotated`, `low_contrast`, `blurred`, `noisy`, `ben_eng_mixed`, and 5-page PDF) all stamped `[নমুনা]` / `FAKE_TEST_DATA`. `TesseractOcrAdapter` explicitly marked UNVERIFIED with transparent host CLI detection (Tesseract binary missing reported plainly without crashes). Multi-step pipeline: virus/magic bytes safety scanner (`BasicMagicBytesScanner` real; `ClamAvAdapterSlot` UNVERIFIED), PDF page splitting via `pypdf`, image enhancement (auto-deskew 90-degree rotation, grayscale conversion, 1.4x contrast normalization), legal document classification, stated-dates-only entity extraction, and bounding box snippet cropping linked to field state machine (`extracted` -> `reviewed` [requires `confirm=True`] -> `verified`). | Complies with SRS §5.3 (M03), §9.3 S4, AC-M03-1..6, and DoD; guarantees 100% CI pass rate independent of host operating system binaries. | Approved (Sprint S4) |
| **ADR-024** | Notice Interpreter, Grounded Explanations & Script Purity | Notice Interpreter (M04) provides 8 structured sections, exact stated dates, Rules Engine relative period computations, and strictly grounded "if you ignore it" fallback (`নথিতে এমন কিছু উল্লেখ নেই। একজন আইনজীবীর পরামর্শ নিন।`). Status is **Built, Not Validated** pending a lawyer-written set of at least 100 notices and lawyer review of 50 outputs. All synthetic evals described as pipeline checks. All mock model runs stamped with `provider="fake"` and experimental banner (`পরীক্ষামূলক মোড: এটি আসল AI বিশ্লেষণ নয়।`). Script purity enforced: certainty labels standardized to `স্পষ্ট`, `যাচাই করুন`, `নিশ্চিত নই` (legacy `পরিष्कार` prohibited). Lawyer sharing correctly cross-referenced to **M08** (M09 is Legal Library). | Enforces strict legal safety, grounded citation truth, and transparent disclosure of mock pipeline validation. | Approved (Built, Not Validated — Sprint S5) |
| **ADR-025** | Reversible Cases vs Legacy Matters Relationship (Decision D08) | Citizen workflow introduces the `cases` table (Sprint S6, M06). Legacy `matters` rows from `legal_saas.db` (15 matters, 5 documents, 1 organization) are preserved strictly intact and read-only. `cases` records link to legacy matters via nullable `legacy_matter_id VARCHAR(64)`. Cases wrap and supersede legacy matters reversibly for citizen workflows without modifying or deleting legacy records. | Guarantees legacy data integrity, zero data loss, and smooth modernization without breaking existing advocate tools. | Approved (Decision D08) |
| **ADR-026** | Case Folder (M06), Deterministic Next Action (M02), and Notifications & In-Process Reminders Architecture (M07) | (1) **Case Folder (M06)**: Extended cases model with `case_parties`, `case_events` (with `date_precision` in `['day', 'month', 'year', 'approximate']`), `case_facts` (supporting active vs proposed distinction), `case_notes` (with strict `include_in_analysis` privacy toggle per AC-M06-5), and `case_documents`. Reversible deletion provides three options for associated documents (`keep`, `unlink`, `delete` per AC-M06-4). Case AI Review executes `case.review.v1` producing 6 structured sections with zero outcome statements and mandatory label `AI বিশ্লেষণ, আইনি পরামর্শ নয়`. (2) **Home & Next Action (M02)**: Time-aware Bangla greeting (`সকাল`, `দুপুর`, `বিকাল`, `সন্ধ্যা`, `রাত`), ProblemInput validation (10–1000 chars, whitespace trimmed, mic disabled with coming soon tooltip), and pure deterministic 10-priority Next Action table (SRS Section 5.2) with auditable `reason_refs` and Bangla explanation modal. Proposed review facts/issues are excluded from next action priority until explicitly accepted by citizen. (3) **Notifications & Reminders (M07)**: In-process scheduler with injectable test clock; computes T-7, T-3, T-1, and 08:00 Asia/Dhaka day-of reminders; strictly rejects scheduling reminders in the past; quiet hours (22:00 to 07:00 Asia/Dhaka) defer non-urgent notices to 08:00 morning digest; SMS escalation uses strictly generic text (`You have a deadline soon. Open AIN-AI.` / `আপনার একটি আইনি সময়সীমা আসন্ন। আইন-AI অ্যাপটি দেখুন।`) with zero case details or PII leakage; delivery receipts, up to 3 retries with 5-minute backoff, and admin failure view. | Enforces strict legal safety, deterministic time-aware logic, citizen privacy boundaries, and zero-hallucination case progression. | Approved (Sprint S6) |
| **ADR-027** | Legacy Matter to Case Mapping and 8 Case Tabs Architecture | (1) **Legacy Matter Mapping**: Legacy `matters` rows from `legal_saas.db` are mapped non-destructively to modern citizen `cases` via `map_legacy_matter_to_case`. The original legacy records remain untouched (read-only); the new case links via nullable `legacy_matter_id`. Client and opponent data map cleanly to `case_parties`, and filing dates map to `case_events`. Reversible and non-destructive. (2) **8 Case Tabs (SRS §5.4 M06)**: Case view strictly aligns with SRS 8 tabs: **Overview** (case summary, status, urgency, parties), **Timeline** (chronological events with date precision `day`, `month`, `year`, `approximate`), **Documents** (associated source notices and case documents), **Tasks** (actionable items with origin, status, priority), **Deadlines** (statutory deadlines, confirmation status, calculation basis), **Notes** (citizen private notes with strict privacy flag `include_in_analysis` and brief sharing toggle `include_in_brief`), **Review** (AI case review with zero outcome predictions and `DRAFT_NOT_REVIEWED` library checks), and **Lawyer** (placeholder for "Share a brief" with verified advocate, ready for M08). | Preserves legacy system continuity while delivering modern modular citizen case workspace adhering to SRS §5.4. | Approved (Sprint S6) |
